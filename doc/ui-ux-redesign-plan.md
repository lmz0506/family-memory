# 拾光 UI / UX 深度改版方案

> 设计主题：把家里的日子，装订成一本可慢慢翻阅的影像日记。
>
> 版本：2026-10-21 · 方案阶段；用于指导后续修改，尚未应用到业务页面。
>
> 配套视觉参考：[打开设计样稿](ui-ux-design-preview.html)。样稿中的家庭、故事、计数和图表均为演示内容，不是当前家庭的实时数据。

## 1. 结论与设计边界

建议保留当前的四个一级入口：首页、时光轴、珍藏、家人，以及现有 Vue 组件和业务链路，重整视觉系统和阅读顺序。界面应像一本当代家庭影像日记：暖白纸面、暖棕文字、珊瑚橙标记，照片有足够面积，文字有明确层级，操作安静而清晰。

改版的重点依次是：阅读、浏览、记录、情感表达。温暖来自照片、文字和家人之间的回应，装饰应为这些内容留出空间。

- **必须保留**：珊瑚橙、暖白、暖棕的主体配色；四个主入口；照片/视频/声音/文字记忆；点赞与回应；时光胶囊；纪念日可见范围；相册与星海双模式。
- **可以重构**：页面骨架、内容层级、卡片形式、字体角色、按钮位置、导航密度、筛选布局、动效、星海的主题表现。
- **本轮交付**：真实现状诊断、设计规范、逐页方案、组件映射、实施优先级和验收清单，以及独立视觉样稿。
- **后续产品决策**：是否调整新用户的默认时光轴模式。推荐新用户先进入相册，保留已有用户的模式偏好；该项应单独确认产品方向后实施，不夹带在换肤中。

### 1.1 本次实际查看范围

已在 `http://localhost:5210` 查看真实登录态下的首页、星海、相册、珍藏、家人，以及记录弹窗，桌面视口为 1280 × 720。已核对路由、全局样式、Tailwind 配置、各业务页面、共享组件、类型及前端 API 声明。

登录、家庭初始化、详情页和移动端的判断以源代码为依据，本轮未进行这些页面的完整实机交互验收。未发布记忆、发送回应、生成邀请码或修改家庭资料。浏览检查中切换了时光轴显示模式，检查结束后恢复为星海。

`family_memory_ui_redesign*.html` 和 `public/preview/` 是仓库中的独立参考稿，不是本次判断现状的依据。真实业务入口以 `src/router/index.ts` 为准；根 README 中部分目录和运行说明已落后于实际结构。

## 2. 当前页面的具体问题

现有界面已有温暖气质、真实照片、中文衬线标题、桌面侧栏和移动底部导航，也已有焦点样式、减少动态偏好和弹窗焦点管理。这些基础值得保留。需要解决的是规则分散、阅读密度和功能层级。

| 现状与证据 | 用户感受 / 影响 | 改版决策 |
| --- | --- | --- |
| `tailwind.config.js:11` 的品牌橙为 `#E76F51`；`src/style.css:15` 的强调色为 `#CC563D`，同时存在 peach、warm、stone 和组件硬编码 | 相同类型的动作和文字表现不同 | 设立唯一语义 token，旧配置只映射同一来源 |
| 首页有大标题、英文眉题、欢迎面板、故事标题、密度控制；侧栏还有深色记录推广卡 | 进入页面后注意力被多个区域分散 | 首页首屏先看故事；页头简化；记录入口固定；英文只作极少量装饰 |
| `MemoryCard.vue:48`、`:50`、`:52` 在照片上叠媒体数、类别、地点、日期，且有渐变蒙层 | 照片被切割；加载失败时信息层覆盖占位内容 | 照片上最多保留一个计数；日期地点移到纸面区；失败时彻底移除图片蒙层 |
| `MemoryCard.vue:72` 在正文为空时补通用抒情文字；文字记忆仍占固定 4:3 的媒体区 | 重复文案挤占真实内容；纯文字也像缺图 | 空正文不补故事；文字、声音、影像使用不同内容模板 |
| 相册在 `TimelineView.vue:112` 从 xl 开始使用五列；日期、标题、作者又压在 4:3 图内 | 在当前 1280 宽屏上卡片很小，文字与失败提示重叠 | 按内容容器宽度决定列数；标题和元信息下移 |
| 星海默认蓝黑底，彩色节点和蓝色控件，与暖白应用框架并存 | 情绪切换大，视觉像另一个产品 | 保留探索机制，统一为暖棕夜景、琥珀光和珊瑚选中态 |
| 珍藏已有良好主题，但大块深棕、亮黄倒计时与多个胶囊面板同时出现 | 倒计时比信件内容更抢眼 | 转向暖白信笺与适量深棕封面，倒计时降低饱和度 |
| 家人页首屏高度较大，邀请入口出现三处；足迹地图明确还是占位功能 | 真正可用的成员与纪念日内容被往下推 | 家庭封面收短、保留一个主邀请入口；纪念日前移；地图占位退出主内容 |
| 当前存在大量 10–12px 的操作和元信息，以及明亮珊瑚橙上的白色小字 | Windows 和移动端阅读吃力，部分文字对比度不足 | 正文 16px、操作 14–16px、元信息 13px；深珊瑚承担白字按钮 |

**运行时观察与界限**：本次首页和相册有部分照片加载失败，其余内置照片可显示；这里只能确认当前页面的失败状态，不能据此判断是存储、地址、网络还是权限原因。视觉改版应完善失败状态，媒体地址排查应另立功能缺陷，不用替换成虚构照片来掩盖问题。

## 3. 视觉方向：暖白纸面上的家庭影像

### 3.1 整体构图

界面保持平静的暖白底，页面结构通过留白、字体和细分隔线建立。照片拥有完整可看的面积；大多数文字位于纯色纸面，少量品牌橙用来指引下一步。深棕主要用于标题、文字和珍藏/星海的特殊场景。

建议按**界面填充区域**估算：暖白及白色约 75–85%，浅暖棕约 10–15%，珊瑚强调约 5–8%。照片本身的自然色不计入此比例，不给所有家庭照片统一套橙色滤镜。

视觉关键词：柔和、清楚、有秩序、有生活感。每个页面最多一个主要视觉焦点；首页焦点是故事列表，珍藏焦点是信，家人页焦点是家人和重要日子。

### 3.2 色彩规范

品牌锚点 `#E76F51` 保持不变。深珊瑚是同色系的可读性变体，不替换品牌识别色。

| 语义 token | 色值 | 用途 |
| --- | --- | --- |
| `--fm-brand` | `#E76F51` | 品牌标识、装饰线、大块非文字强调、图表主色 |
| `--fm-action` | `#BF4C36` | 常规白字主按钮、链接、小号强调文字 |
| `--fm-action-hover` | `#A83E2B` | 主按钮悬停 / 按下加深 |
| `--fm-brand-soft` | `#FDF0EC` | 导航选中底、轻标签底 |
| `--fm-page` | `#FFFAF5` | 全局暖白底 |
| `--fm-surface` | `#FFFDF9` | 纸面卡片、弹窗 |
| `--fm-surface-raised` | `#FFFFFF` | 浮层、照片边衬 |
| `--fm-surface-muted` | `#F7F1E9` | 低层级分区、骨架屏、上传底 |
| `--fm-text` | `#332E2B` | 标题、正文主文本 |
| `--fm-text-secondary` | `#70543E` | 正文说明、次级信息 |
| `--fm-text-muted` | `#806249` | 日期、作者、辅助文字 |
| `--fm-border` | `#E9DDD1` | 装饰性分隔、非交互卡片轮廓 |
| `--fm-control-border` | `#A58A75` | 需要清晰识别的输入/复选控件轮廓 |
| `--fm-night` | `#231B17` | 星海画布、局部深棕封面 |
| `--fm-night-surface` | `#352820` | 星海工具、浮层 |
| `--fm-night-text` | `#FFF1E5` | 深棕场景主文字 |
| `--fm-amber` | `#E4B57B` | 珍藏与星海的暖光，不用作浅底小字 |

反馈颜色单独保留：成功 `#24785C`、提醒 `#8B5E20`、错误 `#B63F35`。这些颜色仅出现在状态提示中，每次同时给图标和文字；不扩展成绿色、蓝色、紫色的品牌卡片体系。“已开启”可以用暖棕文字和已开封图标，无需大块绿色。

**已计算的对比度**（sRGB、实色、不透明）：

| 前景 / 背景 | 比值 | 使用结论 |
| --- | --- | --- |
| 白字 / `#E76F51` | 3.09:1 | 不用于常规 14–16px 白字按钮；品牌色保留在合适位置 |
| 白字 / 当前 `#CC563D` | 4.23:1 | 仍未达到普通文字 4.5:1 |
| 白字 / `#BF4C36` | 4.88:1 | 可用于常规主按钮 |
| `#BF4C36` / `#FFFAF5` | 4.71:1 | 可用于小号链接和强调文字 |
| `#806249` / `#FFFAF5` | 5.38:1 | 可用于元信息 |
| 当前 `#967960` / `#FFFAF5` | 3.89:1 | 普通小字需要加深 |
| `#A58A75` / `#FFFAF5` | 3.12:1 | 可作为需识别的控件边界 |

普通文字目标至少 4.5:1；大字至少 3:1；有意义的非文本控件和焦点轮廓目标至少 3:1。装饰分隔线可以更淡。半透明叠层、照片上的文字、禁用态应单独检查，不能直接套用上表。

### 3.3 字体与排版

中文界面由中文字体建立节奏。无衬线承担正文和所有操作，衬线只给少量页面标题、纪念日数字或信件标题。不要让每个标签、数字、按钮都混用不同字体。

| 角色 | 桌面 / 移动 | 字重 / 行高 | 说明 |
| --- | --- | --- | --- |
| 页面主标题 | 32 / 28px | 600 / 1.4 | 中文衬线，每页一个 |
| 分区标题 | 22 / 20px | 600 / 1.45 | 可用衬线，避免长段落 |
| 故事卡标题 | 18 / 18px | 600 / 1.5 | 无衬线，最多两行 |
| 详情正文 | 17 / 16px | 400 / 1.85 | 阅读宽度 640–720px，保留用户换行 |
| 普通正文 / 表单 | 16 / 16px | 400 / 1.7 | 移动输入不小于 16px |
| 导航 / 按钮 | 15 / 15px | 500–600 / 1.4 | 以文字可读为先 |
| 元信息 / 标签 | 13 / 13px | 400–500 / 1.5 | 日期、作者、数目 |
| 非必要品牌辅助字 | 11–12px | 500 / 1.5 | 不承载功能、权限、错误等信息 |

推荐正文栈：`"PingFang SC", "Microsoft YaHei", "Noto Sans SC", system-ui, sans-serif`。标题栈：`"Noto Serif SC", "Songti SC", "SimSun", serif`。Windows 没有 Noto 时，宋体仅用于短标题；要保证跨设备一致，可后续打包授权允许的中文字体子集。

现有 `index.html` 实际请求 Google Fonts，README 声称不依赖在线字体，两者不一致。建议首屏依赖系统字体；需要自托管字体时使用 WOFF2 子集与 `font-display: swap`，不要让中文大字体阻塞内容。正文中文不设置负字距；标题字距 0 到 0.02em；大写英文装饰可单独用 0.12em。日期、倒计时、图表数值用 `tabular-nums`。

### 3.4 间距、圆角、边框与阴影

- 基础间距：4、8、12、16、24、32、40、48、64px。相关内容靠近，不相关区块拉开。
- 桌面页面边距 40px；1024–1199px 为 28px；768–1023px 为 24px；手机为 16–20px。
- 页面头与首个内容区间距 32px；分区间 40px；卡片间 24px；卡片内边距 20–24px；标题与说明间 8px；图标与文字间 8px。
- 圆角统一为：小标签 6px、表单与常规按钮 12px、照片 12px、内容卡片 16px、主封面/弹窗 24px。胶囊形只给筛选组与确有需要的计数，不让所有元素都成为药丸。
- 关联部件遵守内外圆角关系。例如 16px 卡片里有 12px 图片，留至少 4px 内边距；满出血照片只继承卡片上缘圆角。
- 卡片通常只用 1px 暖色细边，不同时叠厚边、内阴影、大投影和渐变。
- 卡片静态阴影可为 `0 2px 10px rgb(74 62 53 / 4%)`；悬停 `0 8px 24px rgb(74 62 53 / 8%)`；浮层 `0 24px 64px rgb(51 46 43 / 16%)`。
- 虚线框保留给上传和空状态；大面积模糊、发光和玻璃质感集中用于星海，普通内容区域以清晰纸面为主。

## 4. 信息架构与公共框架

### 4.1 导航与记录入口

桌面侧栏推荐从 256 收为 **224px**，导航项高 48px，图标 20px。选中态用浅珊瑚底、深珊瑚文字和 3px 侧标记，避免仅依赖颜色。折叠后为 72px，必须提供焦点可见的名称提示。

移除侧栏底部深色口号推广卡，保留安静的账号/家庭区。当前头像的绿色在线点未看到实时在线状态绑定，应移除，避免制造在线语义。齿轮图标目前实际打开退出菜单，改成“更多”图标；只有设置入口真正可用时才使用齿轮。

记录入口分配为：桌面首页与时光轴页头一个主按钮；珍藏页主按钮为“封存一封信”；家人页主按钮为“邀请家人”。桌面侧栏可保留低权重“记录”快捷入口，但不再放第二个高饱和大按钮。移动端首页/时光轴提供一个带“记录”标签的浮动入口，页头不重复主按钮；珍藏和家人用本页动作。

详情页应按来源点亮首页、时光轴或珍藏导航。当前通过 `route.name === item.name` 判断，详情状态容易全部未选中；新增来源上下文时也要支持直接链接的默认归属。

### 4.2 顶部与内容容器

顶栏保持 64px，分隔线轻淡。全局搜索宽 320–440px；本地日期降为可隐藏的辅助信息。搜索只承诺现有实际支持的检索范围，不能因占位词“照片、家人”让用户以为支持识图或按人物筛选。

内容容器最大宽 **1200px**，居中。标准卡片模式按内容区宽度决定列数：小于 600px 单列；600–919px 两列；920px 起三列，间距 24px。尽量使用容器查询，而不是仅依据整个屏幕的 xl 断点。

首页保留舒展 / 标准 / 紧凑偏好：舒展卡片最小宽约 340px、标准约 280px、紧凑约 220px，列数由可用宽度决定。每个密度都需明确字号与隐藏规则：紧凑可以隐藏摘要，但不缩小标题和主要操作字。移动端不展示密度切换。

移动底部导航推荐固定 64px 内容高度加安全区，以暖白实底或轻透明表面呈现。给滚动容器预留导航、浮动按钮和安全区的实际总高度，确保最后一项和键盘焦点可见。不要用单个固定 `88px` 假设覆盖所有设备。

## 5. 逐页改版

### 5.1 首页：先看到值得翻开的故事

**任务**：看最近的家庭记忆，并轻松记录一件小事。

建议从上到下：简洁问候与家庭名 → 页标题和记录入口 → 故事数量与密度工具 → 记忆网格 → 分页/加载更多。欢迎区不再套大圆角描边卡，页头约 112–144px 即可；“把日子，一页页留住”保留为标题，不再叠多条口号。

把首页顶部的“影像瞬间”计数移到低权重概览或家人页。只有准确确认 `photoCount` 的业务统计口径后，才使用“照片”“影像”之类标签，不把它当作记忆条数。

**故事卡结构**：

1. 4:3 影像，使用原照片自然色；右上角仅显示多媒体数量，例如“1 / 6”。单张不显示数量徽标。
2. 发生日期 + 地点，13px 暖棕文字。未记录地点时直接省略，不在卡片反复提示缺失。
3. 18px 标题，最多两行；摘要最多两行，正文为空时省略摘要。
4. 作者和一个主要标签。作者头像优先用真实头像，没有头像再用首字占位。
5. 底部 44px 高操作区域，喜欢与回应，右侧“翻开”或标题链接。图形可小，点击区域至少 44 × 44px。

日期主次应一致：卡片优先展示 `memoryDate`，它是故事发生日期；`createdAt` 在作者区需要时标为“记录于”。不把“今天上传”暗示成“今天发生”。不把缺失地点补成“家庭记忆”。

**内容变体**：文字卡直接展示标题和 4–6 行正文，用淡暖纸面与短边标记，不再伪造 4:3 缺图区；声音卡展示播放、时长和正文，波形仅在能从音频真实提取时绘制；视频卡有静态封面与明确播放按钮，列表不自动播放。舒展/标准模式按网格行对齐，不为了高度齐整填充虚构文字；紧凑模式优先统一缩略图与两行标题。

**那年今日**：前端已有 `memoryApi.today`，但当前首页未渲染该模块。可作为 P2 的低高度横向回忆条，置于列表上方或右侧；仅在有结果时显示，不能拿任意历史照片冒充“今天”。

**长列表**：桌面分页缩为首尾页、邻近页和省略号，不渲染所有页码。移动端保留增量加载，补可操作的“加载更多/重试”；失败时停止自动重试但保留已加载内容。

### 5.2 时光轴：有序回看与沉浸探索

**相册**与**星海**表达同一份时间数据：相册帮助快速找回，星海提供情绪和探索体验。保持两种模式，切换时保留关键词和时间位置；不强制回到默认年份。

**相册模式**：

- 桌面左侧 96–120px 年份索引、右侧月份内容；空间不够时改为顶部横向年份条。
- 月份标题用“2026 年 · 8 月”，旁边显示本组条数，确保跨年时可辨认。
- 照片下方独立显示两行标题和日期；去掉每张图上的作者/地点/标签大蒙层。
- 仅当前年份/当前月给珊瑚色标记，普通年份使用暖棕；年份选择可通过键盘操作。
- 一个明确的筛选面板承担关键词与年份，不在顶栏和页面里放两套相似搜索框。全局搜索提交后进入当前模式并显示清楚的关键词状态。
- 当前相册请求固定 `size: 50`，需要分页或按月加载，不能把前 50 条误标为全部。每月条数使用真实汇总，不用局部加载结果推算全年。

**星海模式**：

- 保留现有年份 → 月份 → 日期 → 记忆/珍藏的节点结构、点选、缩放、面包屑和有界加载机制。
- 画布从蓝黑改为 `#231B17` 暖棕夜景；工具面板 `#352820`；文字用暖白，弱化蓝色金属高光。
- 节点限制在琥珀、桃橙、珊瑚、浅暖白色系；选中用亮度、尺寸、轮廓和文字共同表达。年份身份依靠标签与位置，不依赖每年一个随机色。
- 同时调整 `universe.css`、`UniverseScene.ts` 背景、`memoryUniverse.ts` 节点颜色和 `NebulaVolume.ts` 的着色器颜色；只改 CSS 无法消除蓝紫星云。
- 默认画面中，真实可交互节点应比装饰星尘突出；少量数据时仍可读，不为“填满”生成假的记忆节点。装饰星点应与数据节点有明确的大小/亮度差别。
- 面包屑位于标题下；显示控制集中在右下一个工具组；时间导航在左下或底部固定区域，两者留出不重叠的安全空间。手机时间导航使用可收起的底部抽屉，展开时收起相机控件。
- 自动旋转默认关闭或第一次进入后由用户主动开启；现有暂停控制继续保留。背景页、阅读抽屉、系统减少动态模式时停止非必要动画，暂停渲染循环或降频。
- 星点交互需要文字列表替代入口；WebGL 不可用、加载失败、低性能或键盘用户均能切到相册继续找回内容。
- 详情关闭后恢复原探索位置。星海搜索可以检索记忆和珍藏索引，相册列表主要展示记忆，两者的结果范围需清楚标注，不能悄悄混为同一个计数。

模式默认建议属于体验变更，单独实施：新用户默认相册，已保存模式的用户继续保留个人选择。如果产品坚持星海首入，仍按本节统一暖色、入口解释和列表替代能力。

### 5.3 珍藏：未来来信的书架

**任务**：理解哪封信能看、哪封信在等待，以及如何封存一封信。

页头为“写给未来的我们”及一句说明，右侧一个主按钮。下一封来信改为纸质信封式重点卡：暖白纸面、左侧深珊瑚小标、标题/收信人/开启日期，倒计时 36–40px 暖棕数字，局部用暖琥珀衬底。深棕封面可保留为窄幅特征区域，避免整块大暗色板占据首屏。

| 业务状态 | 表达 | 可执行动作 |
| --- | --- | --- |
| 未到开启日 | 锁图标 + “待开启” + 日期 + 剩余天数 | 查看封存信息 |
| 到日且接口允许查看 | 开封图标 + “可以打开了” | 查看信件 |
| 已开启 | 开封图标 + “已开启” | 重读这封信 |

现有前端类型主要提供 `opened`、`daysRemaining` 和 `openDate`，并未提供独立的“可开启但未读”状态。第一阶段只映射已有“待开启/已开启”；只有后端契约能明确区分时才增加第三态。“0 天但 opened=false”以接口状态为准，显示“开启状态待确认”，刷新后重试，不直接展示正文。

“自动开启”是当前页面文案，本次未验证服务端触发机制。改稿先使用“可于 YYYY 年 M 月 D 日查看”，避免承诺通知、自动投递或自动阅读行为。

待开启卡片只显示允许公开的封存元信息，不能因为列表响应有 `content` 就把正文摘要渲染出来。胶囊在星海也只能展示允许返回的索引元信息。信封插画使用少量 CSS/SVG 线条，每封不必重复占 110px 的大插画。

封存表单保留标题、收信人、正文、开启日期；提供可见字段标签、日期说明和提交前摘要。关闭含未保存内容的表单时保留草稿或提示；日期应按真实后端规则校验。

### 5.4 家人：关系与重要日子

桌面家庭封面高度建议 180–220px，手机 160–200px。封面主要呈现家庭名、一句家庭介绍和成员头像组；照片用局部渐变保证文字清晰，避免整张覆盖浓厚棕色蒙层。

下方最多保留三项轻统计：家人、记忆、相伴记录天数。名称与真实字段含义对应，`recordDays` 的计算口径应先确认，不把它说成家庭成立时长。珍藏数可放低权重摘要。

成员用紧凑关系卡：头像 48px、姓名 16px、身份 13px、必要权限标记。每人“累计发布”数降级为辅助信息，不做排行、奖杯或家庭贡献排名。当前“查看家庭记录”实际跳到同一个家庭时光轴，不改名成“查看 TA 的故事”；按作者筛选只有在接口支持后再增加。

邀请只保留页头主入口；成员列表尾部可以有低权重文字入口，但取消第三张大虚线推广卡。邀请码弹窗突出代码、复制、有效期和使用限制，复制失败保留手动选择路径，不添加当前未实现的二维码流程。

“重要的日子”移到成员区旁边或下一行优先位置，日期牌 + 标题 + 剩余时间 + 可见范围。保留 `PRIVATE / FAMILY / SPECIFIC` 的现有语义，默认仍是仅自己；编辑/删除仍服从 `canManage`，不因视觉统一而扩大权限。

当前足迹图谱仅是“敬请期待”占位图，本轮从主内容移除或收为一句低权重提示。真实地图作为后续产品项，需要地点数据结构、地理编码、权限与地图能力，不纳入第一阶段换肤。

### 5.5 记忆详情：一篇值得读完的日记

阅读内容最大宽 720px；影像区可宽至 960px，使用 `contain`，不裁掉合照人物。列表缩略图允许裁剪，详情与全屏始终能看到原图。

建议顺序：带来源的返回 → 发生日期/地点 → 标题 → 作者 → 主要影像与缩略图 → 正文/声音 → 喜欢与家人回应。移动端标题和关键背景尽量不被大图完全推到第二屏。

去掉每篇重复的固定引语“这一刻，被家人认真收藏”；正文为空则省略正文区。正文 16–17px，行高 1.85；回应 15–16px，替换当前大量 12px 的评论文字。缩略图增加明确名称和当前张数，键盘和屏幕阅读器可定位。

返回后恢复原列表页码、关键词和滚动位置；从星海返回恢复星海层级。直接打开详情链接时仍提供明确的“返回首页/珍藏”退路。

### 5.6 记录弹窗：先留下内容，再补整理信息

桌面宽 600–640px，24px 圆角，内边距 28–32px。手机使用近全屏编辑面板（可保留 20–24px 上圆角），兼容软键盘和安全区，不用很多层嵌套滚动。

顺序：标题 → 正文 → 照片/视频与声音 → 发生日期 → 可展开的地点/标签 → 提交区。必要信息有清楚标签，“地点/标签（可选）”直接写明；折叠整理项前先判断里面是否有校验错误。

- 保留标题必填、最多 9 个媒体等现有约束，表单重排不改变接口语义。
- 默认发生日期继续按现有本地日期逻辑；用户明确填写历史日期后，不随关闭/重开无声重置。
- 上传区展示真实预览、文件序号、移除、逐文件进度和失败重试。超过总容量需解释被忽略的数量，不能只对单次选择超过 9 个提示。
- 当前组件已有 `useDialog`，保留其焦点圈定、Esc 和焦点回归；增加背景不可交互和有改动时的关闭策略。草稿暂存属于功能增强，不声称已经具备。
- 焦点样式按字段形状设计：输入外框 2px 深珊瑚、2px 暖白间隔；标题/正文编辑区用柔和边界，避免一个与字段形状无关的尖角大框。
- 手机打开时先聚焦面板标题，不自动唤起键盘；点击标题/正文后再输入。
- 保存期间展示上传/保存状态，防止重复提交；失败保留内容与已上传文件，给下一步操作；成功关闭并恢复触发位置。

### 5.7 登录与家庭初始化

延续“照片 + 暖白表单”的现有基础，统一到本方案的深珊瑚动作色、16px 输入和 12px 圆角。照片可见时使用局部暗部叠层保证标识可读；移动端保留简洁品牌头。

创建/加入家庭都用珊瑚与暖棕，取消加入分支独立的蓝色主题。邀请码有持续可见标签、粘贴支持和清楚错误。登录/注册按模式使用正确的自动填充语义；正式页面不预填演示账号密码。登录后的 redirect 行为属于功能校验，不能只在视觉稿中承诺。

## 6. 图表与数据表达

图表的任务是帮助找到故事。家庭产品首页不需要堆折线图、增长率和完成率，也不把亲情设计成活跃度竞赛。

第一阶段使用：轻量数字概览、月份分组数量、日期牌、胶囊剩余天数。P2 可以在时光轴上加入 **12 个月记忆分布柱图**：与所选年份一致、单一珊瑚色、选中月份加描边、灰棕轴线，柱下有月份，悬停或焦点显示“8 月 · 12 段记忆”，点击滚动至月份/触发按月加载。

每月分布可复用 `memoryApi.timeline` 的年月计数，但要先验证接口统计范围。星海 overview 同时含记忆与珍藏，不直接拿总和充当相册记忆量。零值画零高度并可通过列表读取；请求失败显示“暂时无法加载”，不能画成全零。提供表格/文本列表替代，不仅依赖高度和颜色。

不画未经实际记录的语音波形、不画无结构地点数据的迁徙轨迹、不显示未经定义的“幸福指数”。本方案样稿的柱图明确是演示，不意味着当前项目已有统计面板。

## 7. 动效与过渡

动效用于解释状态，不作为常驻装饰。基础缓动 `cubic-bezier(.2,.8,.2,1)`，只为确有变化的属性声明 transition，逐步移除 `transition-all`。

| 场景 | 建议 | 时长 / 范围 |
| --- | --- | --- |
| 按钮 hover / focus | 背景加深、轮廓清晰 | 120–160ms；颜色反馈尽量局部 |
| 按钮按下 | 轻微缩放 | 100ms，0.98；减少动态模式取消 |
| 故事卡 hover | 阴影加深，最多上移 2px | 180ms；触屏不依赖 hover |
| 分段切换 | 小滑块移动或淡入 | 180–220ms；固定分段宽度，避免每次弹性改宽 |
| 页面进入 | 主内容整体透明度 0→1，位移最多 6px | 200–240ms，一次；不逐卡长队列延迟 |
| 照片切换 | 同尺寸框内交叉淡化 | 160–200ms，不改变列表高度 |
| 弹窗 | 遮罩淡入，面板轻移 8px | 打开 220ms / 关闭 160ms |
| 点赞 | 图标填充变化，可一次轻弹 | 160–180ms，最大 1.12；无粒子喷射 |
| Toast | 淡入 + 6px 位移 | 180ms；停留约 4–6s，可暂停/关闭 |
| 星海聚焦 | 沿现有路径接近，允许中断 | 450–650ms；减少动态时立即定位/短淡化 |

优先动画化 transform / opacity。必要的颜色/阴影反馈限制在小控件，避免整屏滤镜和背景位置不断动画。骨架使用固定几何与静态暖色块；短促淡入即可，减少动态时关闭扫光和闪烁。

`prefers-reduced-motion` 不仅覆盖 CSS，还应作用到 Three.js 相机、旋转、粒子和后处理；文档不可见时停止无意义帧循环。不得因减少动态而隐藏必要进度或禁止用户操作。

## 8. 状态、无障碍与响应式要求

### 8.1 必须设计的状态

| 状态 | 呈现与操作 |
| --- | --- |
| 初次加载 | 同最终卡片尺寸的暖色骨架，保持标题/工具稳定 |
| 初次空数据 | 一句具体解释 + 一个对应动作，例如“记录第一段记忆” |
| 筛选无结果 | 显示当前条件，可清除筛选；不误导为家庭没有数据 |
| 整页请求失败 | 说明加载失败、重试；保留导航和可用的已加载数据 |
| 单图失败 | 保留占位比例，图标 + “照片暂时无法加载” + 重试；撤下蒙层/媒体播放覆盖层，重试可点击 |
| 缺少正文/地点/头像 | 省略可选文字；头像首字代替；不补写用户没写的故事 |
| 上传/保存中 | 真实进度、明确阶段、防重复；不提前显示“已保存” |
| 胶囊未开启 | 显示封存信息，正文不可见 |
| 长文本/大量标签 | 标题两行、省略摘要、标签最多两项 + 数量；详情完整展开 |

### 8.2 交互和无障碍

- 操作用 button，跳转用 RouterLink；珍藏卡当前用 button 调路由，后续改为链接，让新标签打开和链接语义正常工作。不要在整卡链接内再嵌重试按钮。
- 图标按钮有可访问名称；装饰图标隐藏于辅助技术；所有表单有持续可见标签或可靠的关联标签。
- 普通交互区至少 44 × 44px，次要紧凑控件如确需更小也要扩展透明热区。悬停提示在 focus 也显示，触屏有等价路径。
- 所有交互有 `focus-visible`；焦点不被顶部、底部、浮层或软键盘遮住。加入“跳到主要内容”链接。
- 弹窗有名称、焦点管理、Esc、关闭后的焦点恢复；嵌套浮层先关闭最上层，背景不可交互。
- 现有 Toast 的 status/alert 语义保留，异步数量和表单错误也需合理播报；错误定位到字段，不只在页面角落闪一下。
- 遵循系统缩放，至少验证 200% 字体/页面缩放；不禁用用户缩放。可在后续增加“阅读字号”设置，第一阶段不以 12px 小字为默认。
- URL 至少保留关键词、年份、模式和需要回退的分页；密度与个人偏好可本地保存。不要把胶囊正文、草稿或邀请码放进 query。

### 8.3 关键尺寸

| 宽度 | 布局 |
| --- | --- |
| 320 / 375 / 390px | 手机单列，16px 边距，安全区导航，单一浮动入口 |
| 768 / 820px | 平板双列或按内容宽度降为单列，底部导航，筛选收为抽屉 |
| 1024px | 224px 侧栏，28px 边距，内容通常双列 |
| 1280 / 1440px | 标准模式三列，1200px 上限；时光轴索引按内容区决定是否保留 |
| 1920px 及以上 | 内容居中并保留留白，紧凑模式可增加列数，正文字号不缩小 |

移动星海标题、底部导航、时间面板、控制组和详情层需绘制遮挡关系。相册、珍藏和家人不直接缩放桌面稿，应重排为单列。横屏与软键盘弹出时，弹窗提交按钮必须可达。

### 9.2 分阶段执行

**P0 · 可读性与基础规则**：统一 token；修复主要按钮和辅助文字对比度；提高字号与触控热区；统一字段/按钮/卡片；完善图片失败交互。先做首页的一个真实卡片和记录弹窗，验证长标题、空正文、失败图片后再推广。收益大，业务风险较低。

**P1 · 四页与详情重排**：公共导航和搜索收敛；首页卡片与密度；相册月份分组和更多数据路径；珍藏信笺；家人和纪念日；详情阅读与返回恢复。保留接口、既有权限与用户模式偏好，逐页验收。

**P1 独立项 · 星海主题**：先只调主题 token、材质/着色器颜色与控件层级，不同时改空间布局算法、索引与加载链路。之后验证少量/大量数据、节点点击、查找、月份进入、珍藏跳转、返回及 WebGL 回退。默认模式变更单列为产品决定。

**P2 · 可选增强**：那年今日模块、月份分布导航图、草稿跨会话保存、按作者筛选、真实足迹地图、阅读字号设置。每项先验证接口/数据/权限，不能用设计稿代替能力实现。

### 9.3 API 与数据能力边界

现有前端已声明年月汇总、按月记忆、那年今日、星海 overview/day/search/year，以及纪念日可见范围；这些可作为后续实现的候选基础，但前端声明不等于已完成服务端行为验证。

未在当前前端契约中确认的能力包括：按人物识别/作者筛选、结构化地理轨迹、多人在线状态、独立的胶囊可开启未读状态、提醒推送、跨设备草稿。第一阶段不为这些能力创建误导性按钮或统计。
