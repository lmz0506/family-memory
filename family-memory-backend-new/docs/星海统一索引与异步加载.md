# 星海统一索引与异步加载

星海首次读取年月日统计，不拉取全部记忆或珍藏。记忆按发生日期归档，珍藏仅按封存日期归档；开启日期继续由珍藏详情接口控制。相同日期只建立一个日期节点，分别记录记忆和珍藏数量。

## 数据与事务

`fm_universe_index` 保存家庭ID、来源类型、来源ID、归档日期和标题副本，以及索引自身主键、时间戳与逻辑删除标志。唯一键为 `source_type + source_id`，两种业务的相同数字ID不会冲突。正文、媒体、锁定状态仍由原业务保存。

发布、标题修改、删除均在原业务事务中同步索引；索引写入服务要求已有事务。任意索引写入失败时，业务写入一并回滚。标题修改的幂等更新不会覆盖已有索引日期，也没有新增日期修改接口。

## 接口契约

接口均位于 `/api/v1`，要求登录并校验当前用户是对应家庭成员。

| 请求 | 参数 | 返回 |
| --- | --- | --- |
| `GET /families/{familyId}/universe/overview` | 家庭ID | `memoryCount`、`capsuleCount`、`years` |
| `GET /families/{familyId}/universe/year` | `year`、`afterId`、`size` | 年份轻量索引批次 |
| `GET /families/{familyId}/universe/day` | `date`、可选 `sourceType`、`page`、`size` | 兼容旧版日期分页，新星海不调用 |
| `GET /families/{familyId}/universe/search` | 可选 `keyword`、`sourceType`、`page`、`size` | 标题搜索分页 |

概要的每年包含 `year`、两类数量与 `months`；每月包含 `month`、两类数量与 `days`；每日包含完整 `date`（`yyyy-MM-dd`）、`day` 和两类数量。只返回有内容的年月日，不含逐条标题、ID或正文。

分页响应包含 `total`、`page`、`size`、`hasMore`、`items`。条目仅含 `indexId`、`sourceType`、`sourceId`、`nodeDate`、`title`。`sourceType` 为 `MEMORY`（记忆）或 `CAPSULE`（珍藏），省略表示全部。页码从1开始，默认每页24，服务端限制每页1至50条。

年份批次响应包含 `year`、`items`、`nextAfterId`、`hasMore`。`afterId` 首次传0，之后传上一批的 `nextAfterId`；按索引ID升序查询，每批默认120、最大200条。不执行总数统计或深度OFFSET分页，不需要版本号。年份使用起始日包含、下一年起始日不包含的范围条件，且限定家庭和有效状态。

搜索仅匹配索引标题，关键词最多120字；百分号、下划线和感叹号按字面转义。空关键词可结合来源类型分页浏览。匹配项的 `nodeDate` 用来恢复完整年月日路径，不需要重新查询所有业务内容。

记忆详情仍调用 `GET /memories/{id}`；珍藏详情仍调用 `GET /capsules/{id}`，保留原开启限制。悬停内容只展示已加载标题，不调用详情接口。

## 前端加载

1. 进入星海即建立背景与控件，再异步请求概要；加载提示不遮挡操作。
2. 按完整概要预计算稳定布局，年月日节点每帧最多加入120个，优先年份、其次月份和日期。
3. 概要完成后自动排队预加载所有年份。默认最新年份优先，悬停或进入某年时优先读取该年的后续批次；最多一个年份请求在途，每批之间让出主线程。
4. 每批轻量索引写入当前星海会话的内存缓存，合并到下一帧补入真实星点。已有年月日和内容节点位置固定、亮度连续，沿用已有着色器材质和动态时间，不重建渲染器或重置视角。
5. 点击年月日只负责聚焦与展开，不请求日期接口、不清空其他日期的星点。日期导航栏的分页只切换已加载内容的显示，不发网络请求。某年尚未完成加载时仍可浏览已有星点；失败后可在该年重试，继续上次成功游标。
6. 搜索仍按当前页查询并聚焦完整祖先路径，结果与后台缓存去重合并；清除搜索后恢复已加载星点。正文和媒体仍点击后读取，已读取记忆详情最多缓存64份。
7. 不使用IndexedDB、localStorage或数据版本号保存索引。离开星海时取消请求、释放缓存；刷新页面重新请求概要和年份。请求取消后即便晚返回，也不会再补入旧场景。

布局预计算仍有同步CPU开销，随后按帧加入场景，并非把全部Three.js工作移到后台线程。初始按有内容的日期规模渲染，后台最终加载全部轻量内容星点；内存随索引数量增长。当前面向普通家庭，未来如达到很大规模，再根据实际性能考虑视野裁剪、LOD和Worker布局。

## 上线与核对

已完成建表和回填的数据库无需重新执行建表。若旧后端在回填后继续接收过发布、改标题或删除，应暂停相关写入，重跑幂等回填及核对脚本后切换新后端。

`database/update.sql` 单独补充全部14张表、123个字段的中文注释，包含枚举和逻辑外键来源；未自动执行。它根据读取时的实际元数据保留类型、字符集、排序规则、空值、默认值、自增和自动更新时间。执行前如又变更了字段结构，需重新核对定义。DDL自动提交。

已有库不要执行 `database/schema.sql`，它是含删除语句的空库初始化脚本。历史迁移脚本和中文注释脚本用途不同。

验证包括独立H2事务回滚、年份范围与游标分页、权限及逻辑删除过滤测试；加载队列的优先级、去重、取消和重试测试；前端生产构建及真实MySQL只读页面检查。页面检查将每批限制为2条，确认未点击即自动读完全部批次、日期切换无请求、清除搜索不丢星点、刷新重新获取数据。集成检查临时使用5201端口，未替换用户运行的5200服务；使用新接口需要重启到新后端版本。
